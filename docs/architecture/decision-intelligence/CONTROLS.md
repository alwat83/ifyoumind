# Security, privacy, cost and latency

Part of the [Universal Decision Intelligence ADR](README.md). Numbers below are proposed limits and release targets unless marked as historical observations.

## Trust and data boundaries

| Risk | Boundary and control | Required assurance |
| --- | --- | --- |
| Another workspace reads a case or its paid evidence | Authenticate through the existing Firebase flow. Verify the token and server-side workspace membership and role before retrieval, idempotency lookup or cache access. Resolve project ownership from the authorized workspace. Grant access through the existing report projection. | Invalid/expired/revoked identity, absent workspace, cross-workspace project and guessed operation ID fail without external calls or evidence disclosure. Anonymous sample behavior remains independent. |
| A question, source, or model message becomes a command | Inputs are data. Tool IDs come from the compiled registry. Decode at both edges and run a static plan. Verify evidence and IDs before presentation. Any future model response is a bounded strict structure over approved claim IDs, with no tool definitions, URLs, arbitrary prose or write privileges. | Test malformed payloads, unsupported scopes, unknown IDs, duplicate/desynchronized references and invalid model responses. Return deterministic language. |
| Private bill data leaves the device | Preserve the Discovery entry and asset boundary. Bill CSV, amounts, row evidence, case IDs, assumptions and identifiers stay in browser memory. Clearing, route exit and tab close discard state. Keep filenames, cell contents and raw input out of logs, browser history, URLs, service workers, browser storage and analytics. The cross-route handoff carries only an allowlisted category. | Keep the static import guard and browser no-network, no-persistence and clear-state assertions for both families and the scenario path. No server-side upload or cross-case join. |
| Personal context is reused beyond the first answer | Preserve the legacy city project contract while #106 and the adapter migrate. New normalized adapter requests send only validated places and a request ID to the Functions boundary; the Census egress sees FIPS/state/vintage data only. Salary may appear locally as user context. A save through the existing authorized flow retains its established persistence behavior. No new silent storage of the raw question or salary. | A wire audit checks each outbound destination. Existing saved projects are unaffected by the transition. Confirm the approved retention and deletion behavior before adding any new workspace case fields. |
| Untrusted URL, unsafe source join or spoofed provenance | Source adapters build URLs from allowlisted origins, datasets and typed identifiers. Reject redirects, unexpected shapes, wrong state/place/vintage, mixed definitions and out-of-range or suppressed estimates. Never follow source links presented by a question or model. Redact credentials from source receipts. | Simulate corrupted, stale, contradictory, and missing data; prove abstention and explicit reason without accepting reused source IDs from another case. |
| Duplicate runs, quota bypass, or unexpected spend | Authorize before lookup. Reserve a scoped operation and free-decision slot through the existing policy, with one transaction shared by old and new writers before a release that changes saving. Budget by UID, workspace and global limits. One shared deadline bounds the static plan. | Concurrent same-key, different-key near-limit, lost response, timeout, old-client and failover tests. An expired worker cannot commit a second project. Quota rejection uses the existing user-facing wording. |
| AI disclosure or incorrect language | Keep production provider calls disabled. A later, separately approved staging test reuses #96's dedicated identity, project and allowlisted model using synthetic fixture packets. Any real-data proposal must document minimization, consent, key restrictions, provider project/retention settings and human acceptance evidence first. | Negative tests for disabled/wrong project and for case facts with private scope. Declined invalid/late responses never delay the first answer or change billing. |

All access checks happen on the server for city work. Browser-only role labels express locality, not a claim that client code can enforce remote access. The workspace result DTO never contains raw statement evidence. The registered tool handlers have no Stripe, entitlement-mutation or arbitrary URL permission. The existing account, pricing, report and webhook paths are the authoritative boundaries.

## Request identity and retries

Keep a short-lived, server-only execution record scoped to UID, organization, operation and a random client key. Reauthorization applies on replay. Bind the key to one digest of the validated normalized request. Replay of a completed operation returns the same authorized result; an active operation returns pending; the same key with different inputs returns a conflict. Network work happens outside Firestore transactions. A lease with a monotonic fencing token protects the final write from a late worker. Budget attempted reads on each admitted run, including failed attempts. No automatic retry from refresh or a model.

The existing writer performs a monthly count before writing a random project ID. Wrapping it with a new caller alone does not eliminate duplicate saves or enforce a concurrent free cap. Before the shared path can ship, use a single allocation/finalization helper for both legacy and new writers, with a transactional per-workspace-period lock, counter/reservation and result record. Seed the applicable period from existing projects under the shared lock or use an equivalent caught-up migration. A successful write commits the one project and terminal operation together. A failed attempt releases an unused slot once; a budget reservation is separate and still charged to the attempt. An unsupported, ambiguous or unsaved partial answer does not create a paid project or spend a free saved-decision slot. Expiration is checked on reads independently of cleanup scheduling. The scheme prevents duplicate committed decisions; a canceled upstream read may already have run and is still counted.

## Cache and retention

- Keep the existing server-only public ACS cache; add a versioned normalized payload keyed on dataset, release/vintage, FIPS, variable set and adapter version. Canonical name resolution uses the existing normalized state/city lookup. A hit never bypasses authorization. Coalesce same-key public fetches in process and share fetch promises only within an admitted request; no cross-tenant caching of private or derived answers.
- Proposed fresh window is **7 days since successful retrieval**. If an upstream request fails, allow last verified data for at most **30 days since successful retrieval**, explicitly labeled with the vintage, retrieval date and stale status. An over-age or missing timestamp yields unavailable. A recently refreshed old release is still old data. Source-version choices are pinned and reviewed separately. Negative lookup cache, if required, is at most 15 minutes and contains only public place keys and typed failure codes.
- Do not cache prompts, bills, identifying links or personalized provider responses. Keep private bill state in memory. Keep saved city project lifecycle under existing access and user expectations. Retain proposed retry metadata for at most 24 hours, with access and expiry enforced before any lookup result is returned. Store the final project rather than a second history copy. Budget telemetry is separate, aggregate, proposed maximum 30 days, subject to actual Cloud Logging retention review before a pilot.

## Per-request targets and circuit limits

Measure from Submit to first evidence-ready rendering. Report warm, cold, partial and error paths separately. Timeouts are shared end-to-end: a slower stage gets only the remaining budget. The values below apply to the proposed adapters and pilot. The current Census function uses per-fetch timeouts and retries and has not been verified against these targets.

| Path | Proposed latency | Hard per-request boundary |
| --- | --- | --- |
| Intent resolution, clarification or unsupported | p95 at most 100 ms on a reference midrange phone | Existing 240-character question input. No network, persistence, or provider call; font/asset loads are outside the submit trace. |
| Tax or electricity | p95 at most 150 ms; 500 ms processing budget after local file read | Existing 2,000,000-byte per-file limit, at most two statement rows per tool, at most two allowlisted local steps overall. Enforce a shared clock and cancel stale work. If a synchronous parser cannot be bounded, keep the pilot in the existing one-tool path until a cancellable boundary is available. Zero post-load network or provider cost. |
| City, cache hit | p95 at most 1.5 s | Two resolved places, 8 KiB normalized input, 64 KiB serialized authorized answer. Reuse existing Project route. |
| City, cache miss | p95 at most 4 s; 6 s first-result deadline (including cold start as seen by the browser, with server abort budget derived from remaining time) | Two places, two vintages, at most four allowlisted Census requests with same-state/vintage deduplication and no automatic retry. Max 2 MiB per source response, streaming byte cap, depth and rows validated. A timed-out dependency yields partial/unavailable. |
| City application data access | Included in the city budget | At most 24 logical document reads and 24 attempted logical writes, including at most two attempts per transaction. Allow two initial auth/plan reads, up to 10 reads and 10 write attempts for admission, four reads/writes for cache, and up to six reads/write attempts for finalization. Keep the remaining headroom for explicit error handling. Meter aggregate/index reads, SDK/provider retries and committed writes separately. If the shared quota helper cannot fit this envelope, keep the pilot off pending measurement and review. |
| Optional future synthetic explanation | After first answer, no impact on its deadline; 5 s attempt deadline | One call, no retries or provider tools, max 1,024 request bytes for the #96 fixture, 16 KiB accepted response bytes, 128 requested output tokens, 768 reported input tokens accepted. Account for schema and framing; returned token rejection is an acceptance rule rather than a pre-call spend cutoff. |

Proposed city pilot caps are 5 admitted runs per UID/day, 20 per workspace/day and 100 global/day, independent of the existing product allowance. These reserve source work; they do not grant free or paid reports. At most 400 upstream requests/day in the worst case before any future raise, and one in-flight operation per UID. Failed attempts count. Use the existing limiter patterns and reserve a cost ceiling before network work. Launch cost target is at most **$0.01 USD per completed city answer** for Functions, Firestore, transfer and telemetry combined, measured by aggregate pilot billing and operation counts; this is a target, not measured unit economics. Model provider budget is **$0** for this release. Stop further admissions when the work budget is exhausted or a source circuit is open. Cloud invoice alerts supplement application reservations and do not enforce an invoice cap.

The existing #96 synthetic guard reserves at most 3 attempts per reviewer/day, 20 global/day and 200 global/month. One historical authorized staging request reported 161 input and 16 output tokens in 3.737 s; it did not establish a p95 or a verified billed cost. At published GPT-6 Luna Standard rates of $0.10 per million uncached input and $0.50 per million output tokens, 768/128 tokens model to **$0.0001408 per attempt** or **$0.02816 at 200 attempts**, excluding taxes and infrastructure. This estimate is not a hard cap. Reverify account limits and framing before any separate authorization. For the future Responses path use foreground requests, `store: false`, no previous response or hosted tools, server validation of the strict output, and deterministic fallback. The storage flag controls application state; standard abuse monitoring has separate retention rules. Project-specific data sharing, retention and eligibility remain prerequisites for any later real-data proposal. ## Telemetry and cost review

Emit bounded labels for domain, tool version, stage, coverage code, cache result, latency bucket, logical reads/writes, provider attempt and bounded usage. Exclude questions, user/organization/project IDs, locations, source cell values, file names, tokens/credentials, URLs and model prompt/completion text. A rotated operational correlation ID can match events in the limited retention window; keep it out of analytics dimensions. Derive estimated spend from usage and dated rate tables and reconcile against Firebase and OpenAI project billing if a provider pilot is ever approved. Record actual and estimated values separately. Report volume, fallback rates, time to first supported answer, and p50/p95 by path. Send alerts only through an existing approved operational channel.
