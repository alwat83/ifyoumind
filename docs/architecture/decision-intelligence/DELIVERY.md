### Proposed implementation PRs

1. **Contracts and fixture harness.** Add pure versioned decoders, typed registry metadata, claim reference validation, formula fixtures and deterministic rendering helpers. Compile both target contexts and prove no Angular or Firebase runtime dependency in the shared code. Keep behind test-only entry points and cover stored project read compatibility.
2. **City adapter and compatibility.** Build from the accepted #106 behavior, normalize verified ACS facts, repair two-vintage citations, add bounded retrieval/freshness, and run under the current authorization. Map only already-authorized project data to the new renderer. Compare new/legacy results in local fixtures without double-fetching or writing to production. Complete the transaction/idempotency dependency before any rollout of new saving behavior. Initially keep existing project IDs, routes, saved records and free/paid rendering. Put the additive projection behind a disabled feature switch for any separately approved staging evaluation.
3. **Browser-only bill adapters.** Map existing structured results and cell references to the common contract while keeping parsing and arithmetic in the current Discovery bundle. Compare outputs at both current entry points. Keep existing examples and corrections. Enable a two-tool plan only after independent status and combined deadline tests for both scopes running locally.
4. **One hypothetical scenario.** Add only the explicitly identified electricity charge edit used to prove dependency recomputation and evidence separation. Reuse existing state and controls if the interaction can be introduced without new navigation. Hold back launch if the test exposes confusion between observed and hypothetical amounts.
5. **Optional presentation experiment.** If clarity evidence supports it and separately approved, adapt #96's synthetic workspace only. Limit output to a selection among existing claim IDs. Compare against deterministic baseline with the same facts, prove the first result is independent, reset staging to flag off, and record results before discussing any broader pilot.

Avoid a separate generic case collection for initial read compatibility. Translate authorized legacy records in memory; keep personal bills and scenario edits local. Existing projects continue to open without a migration job. Store any future normalized workspace revision additively to the existing protected record only after retention, compatibility and access testing. No default backfill; never synthesize missing historical references. Disable the new renderer and fall back to the existing one for rollback. A rollback must also keep historical paid projects readable, preserve completed idempotency claims for their short lifetime, and leave billing settings unchanged.

## Automated evaluation

Use blind fixture IDs that describe test families without embedding customer data. CI runs fixtures and emulator or browser-local harnesses with provider and public network transports blocked or simulated. Source-contract tests pin public, attributable snapshots and versioned metadata. External drift sampling and any approved staging benchmark run outside PR CI with synthetic inputs and a separately agreed work budget.

| Dimension | Fixture matrix and measurement | Proposed acceptance |
| --- | --- | --- |
| Intent and effort | Compare known and ambiguous place names, abbreviations with state, missing/invalid salary, single-city housing, personal cost comparison, unsupported rate, tax correctness, bill change, mixed topic and vague request. Track submit→supported finding, intervening actions, and clarifier count. | 100% golden routing cases correct. The #106 complete question remains one submit after entry. On a missing state, ask one necessary clarification and retain recognized input. Report both denominators and the number of blocked or unsupported tasks. |
| Arithmetic | Golden ACS values and vintage comparisons, tax deltas/reconciliations, electricity total and consumption deltas, equal/unequal dates and day lengths, zero usage or earlier values, USD/kWh precision, mixed units, out-of-bounds and exact-match replay. Add property tests for order invariance under row permutation, signed differences, sum conservation, and supported scenario recomputation. | 100% of numeric and scenario golden cases and properties pass. Invalid denominator/period/charge split yields unavailable where appropriate. No alteration of baseline facts by scenario actions. |
| Claim support | Resolve every typed numerical reference to source cells or ACS variables/FIPS/vintages. Feed the validator cases with missing, wrong-domain, wrong-vintage or cyclic refs, unsupported conclusions, a model requesting unknown claims, conflicting estimate labels and invalid derivations. | 100% of rendered numerical claims have valid value, formula where relevant, and source refs. PR checks use the repository's fast web suite, Functions tests, authorization rules and emulator suites, Discovery isolation and browser tests, and the visual comparison workflow when runtime work changes an affected route. The product acceptance step pairs automated correctness with a small authorized comprehension walkthrough. Ask whether a user can state the first supported finding, its limits and the next action. Record anonymized outcomes and no acquisition or revenue claims without measured evidence.

## Review gates

Review architecture and #106 independently. A first build should deliver the pure fixture contract and prove that real request scopes and evidence round-trip before wiring UI. The release decision needs exact implementation and synthetic verification evidence, migration/rollback proof, and separate authorization. This record does not approve production changes, customer-data access, or paid API use.
