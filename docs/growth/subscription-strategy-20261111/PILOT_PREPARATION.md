## Allowance hazards and verification

| Risk | Mitigation and decisive test |
| --- | --- |
| Double grant from the same renewal or late events | Use Stripe-signed raw request body, account/mode and Price allowlists, workspace/customer binding, canonical invoice period and both event and invoice/period idempotency. Out-of-band, manual, zero-value or unrecognized lines go to review. Test same event, different event IDs for the same invoice, Checkout and invoice in either order, and a late renewal after a terminal or newer event. |
| Two tabs or owners spend the last credit | Both requests read and update the same period ledger in a Firestore transaction. Reserve with a project key and expiring attempt token. A later attempt cannot finalize an earlier token. Test independent concurrent projects at last credit, two requests for one project, duplicate finalization, timeout, and stale-token completion after reclaim. |
| A checkout or old marker arrives during an unlock | Use the same project access invariant across new credit spends and existing one-time fulfillment. A completed purchase or legacy unlock bypasses credit consumption. For an eligible pilot project, serialize choice while either purchase attempt is active and reconcile an unconfirmed Checkout before enabling another action. Recheck project access inside finalization and release the reservation if another valid grant landed. Test both settlement orders and existing markers with missing new fields. |
| False reset, expired credit, or ambiguous state | Use the verified paid invoice-line interval in UTC. Display the exact date in local format. Failed renewal issues no next allowance. A paid retry within its valid interval grants once. A reservation accepted before expiry may finalize within its original bounded lease against the original grant when authorized and unreversed. Test exact boundary, delayed payment, no active grant, cancel schedule/undo, and current-period checkout history. |
| Refund, dispute, or canceled subscription revives credits | Reconcile reversals to the original payment and interval. Hold unused credits on full reversal or open dispute only under the approved policy. Stale delivery cannot restore the grant. Keep unlocked and purchased access. Test terminal cancellation, full and partial refund, dispute open/won/lost, operator repair in dry run and a failed or revoked in-flight reservation. |
| Work happens before the report limit | Current create path computes and stores full output before limiting access. For pilot flows, cap preview creation at the workload entry and reserve before any incremental full generation. Reuse existing durable full output when present. Record actual compute even when a paid report is never unlocked. Test concurrent free previews, retries and rate limits, and check the API and rules never expose full fields before entitlement. |
| Legacy plan or workspace authorization drifts | Keep $39 Pro and $79 access logic separate from pilot grants. Require owner/admin for billing and credit-consuming actions, use server organization membership and Stripe linkage, and preserve existing read rules. Verify fixtures for active and lapsed Pro, purchased reports, missing fields, unauthorized roles, cross-workspace IDs, and mixed legacy/pilot webhook events. |

## Handling the $79 one-time option

The current $79 checkout and a Starter credit can unlock equivalent reports. Making the $79 purchase a peer plan card risks implying greater accuracy or extra deliverables and can make both prices feel arbitrary. A single-decision customer may still value a one-time charge, especially when they cannot commit to monthly billing.

For eligible pilot users, put the two subscription options in the plan comparison. Include a clearly visible **“Prefer one purchase without renewal? One Decision Report · $79 one time”** link on the same screen before payment. The link leads to an explicit choice that states both routes unlock the same full report. Show the immediate amount, cadence, report allowance and cancellation terms side by side in that choice. Keep the one-time path visible with keyboard and assistive technology. Use neutral copy, no preselected option, no claimed quality difference, and no fake crossed-out reference price. Keep the existing path and history for customers outside the pilot. Preserve all project access markers, receipts and customer history. Keep current product, amount and subscription terms during this preparation. Any retirement or repricing needs a separate decision.
