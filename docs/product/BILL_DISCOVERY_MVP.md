## Proposed MVP

Support **one validated US county property-tax layout and one validated US residential electricity layout**, each as an issuer-downloaded, text-layer PDF. Publish the exact issuer, revision/example, supported periods and exclusions once validated. Start with USD, kWh, one property or meter, one current statement and one optional prior statement. Pick the issuers from accessible, authorized fixture coverage and permitted users with a real bill. Keep both current CSV schemas and synthetic examples. Offer **Enter the key numbers** for unsupported layouts, scans, images, encrypted files and cases where extraction confidence is insufficient. Typed evidence is labeled user-entered. A failed file never triggers a server upload. OCR, image intake, arbitrary PDFs, external lookups and AI explanations are later decisions.

| Input | One useful result | Optional second statement |
| --- | --- | --- |
| Property tax | Current annual amount billed and the largest verified component if the component list reconciles. Use the labeled tax year and billed levy, excluding prior balances, payment amounts, interest or installment totals. | For the same confirmed property and compatible consecutive years, show signed dollar difference and percentage when the earlier amount is positive. Attribute change only to consistently defined lines that reconcile on both statements. Label uncategorized amounts and suppress contribution claims when mapping or reconciliation is incomplete. |
| Electricity | Current-period electric charges, kWh and billing days. Show the whole-bill average when kWh is positive. Exclude prior balance, payment, deposit and unrelated services. Combined or net-metered bills, estimated readings or credits require an explicitly validated template and definition, or a clearly limited result. | For the same confirmed service/meter and non-overlapping comparable periods, show current charges and usage changes separately. If periods differ in length, show both durations and kWh/day as context when dates are unambiguous. Explicitly flag season, estimated readings and plan differences when supported by the source. A whole-bill average is total electric charges divided by kWh. An actual tariff needs a labeled comparable line and unit. |

Use integer cents and bounded thousandths of kWh, UTC date arithmetic with each issuer's inclusive/exclusive convention, and display-only rounding. Missing, ambiguous, inconsistent and zero values remain distinct. A zero baseline yields no percentage. Present verified signed offsets where supported and omit misleading shares for net changes with offsets or ties. Keep two-period arithmetic separate from possible explanations. An evidence panel shows both source values, page and field label or exact CSV cell, the formula, and what the statement cannot establish. Single-bill results explicitly state that change requires a prior statement. Users confirm the same property or meter without typing identifiers, and verify the tax year or bill period and amounts before findings are shown. Changes invalidate dependent calculations. A correction is marked user-confirmed, with its source status, and does not inherit unverified extraction provenance.

## Architecture and privacy

`/discover/ → choose category and read privacy notice → local PDF worker, existing CSV, or typed fields → template and field validation → confirm critical inputs → deterministic finding → evidence or clear`.

- **Parsing.** Evaluate a pinned, security-reviewed, self-hosted PDF.js build in an isolated worker, using selected file bytes. The public app and existing CSV bundle entry retain their current relationship. Text extraction only, using allowlisted labels and positioned text on expected pages. No embedded scripts, attachments, form actions, external references, links, fonts from the document, or executable preview. Only same-origin static worker/module assets, loaded lazily. Keep `connect-src 'none'` on the page and worker, test worker asset headers and avoid permitting `blob:` workers, CDN calls or unsafe script evaluation. If a browser/runtime cannot keep these guarantees, use typed fields. [PDF.js documentation](https://mozilla.github.io/pdf.js/examples/index.html) · [PDF.js security policy](https://github.com/mozilla/pdf.js/security/policy) · [Worker CSP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/worker-src)
- **Canonical fields and evidence.** Each adapter returns only allowlisted financial/period facts with template version, source index, page and field label or CSV cell, and status (source, ambiguous or user-confirmed). Keep the bounding reference if it can be verified without exposing the full page. No OCR score or unsupported confidence percentage. Unknown layouts, column shifts, revision mismatch, competing totals, missing units or inconsistent dates must lead to review or fallback, never a silent guess. Store no full text in UI or evidence. Do not collect names, street addresses, account/meter/parcel IDs, filenames, payment barcodes or extracted addresses. Support issuer-provided redacted copies that leave required fields intact. Render evidence as escaped text.
- **Before processing.** Place a short disclosure next to file selection: “We read supported bills in this tab. We don’t upload the bill or save a copy. Choose only bills you’re allowed to use.” Identify supported formats and provide a privacy link. Publish the claim only after network and storage tests pass. The actual parse starts from an explicit selection/action after disclosure. Future external processing needs a separate off-by-default action before transmission naming the recipient, purpose, fields, retention/deletion and available local alternative. Show the user the minimum redacted data to be sent. No silent fallback or inherited consent.
- **Retention and deletion.** Bytes and raw extraction live in worker memory during the run. Terminate the worker and release the bytes and raw text after returning the minimal facts. Clear the picker and revoke object URLs if any. Keep confirmed facts only in volatile page state until clear, replacement, category change or exit. Abort pending work, reset on pagehide and restored history, and ignore stale results. Verify no cookies, local/session storage, IndexedDB, cache writes, analytics, logs, URL data or crash-report payloads with bill content. Clearing removes app state. The original file and browser/OS memory remain under device control. No save, download or share workflow in this slice.
- **Limits and abuse.** Proposed starting limits: one worker, sequential parsing, two files per comparison, 5 MB each, five pages each, 40,000 text characters per document and a 5-second per-file deadline with cancellation. Check suffix, magic bytes, claimed type where present, page count, text/resource bounds and validity. File or MIME checks alone cannot guarantee safety. Abort on timeout/memory pressure and provide a recovery action without printing the filename or parser payload. Use a patched parser and test malformed/truncated, oversized, encrypted and unsupported files in isolation. No public upload endpoint, parsing quota service, or hosted processing spend. Keep the PDF entry removable independently from CSV and examples.
- **Cost.** No per-bill model/OCR/Functions/Firestore request is proposed. Hosting transfer, initial parser download, mobile CPU/memory and maintenance/support still have costs. Measure compressed lazy assets, warm/cold transfer, p50/p95 parse time and peak memory on reference devices before launch. Proposed performance budget is up to 1 MB compressed lazy parser assets and p95 under 3 seconds per supported file on the reference mobile devices, with unchanged initial Discovery load budget. Use actual Hosting transfer and contracted rates for the cost estimate. No hosted cost was measured in this phase. An external fallback would need its own priced estimate, enforceable anonymous abuse controls, budget and retention/deletion review.

## First use and acquisition

From the existing homepage, use one accurate entry such as **Understand your bill** when the feature is available. On Discovery pick tax or electricity, see the privacy notice and choose a supported file or type a few fields. Keep the labeled synthetic example available. Confirm only essential extracted inputs. Lead with one result, then **Show the evidence**, **Compare with an earlier bill** and **Clear my data**. Optional sign-up can appear after the finding. Copy should say it opens the existing workspace and leaves the bill behind. Treat an optional sample link as a separate path for a business/location decision. No implied saved bill, household report checkout or subscription inclusion.

Start measurement with small, consented observations of already-permitted participants using their own bills on their devices or approved redacted specimens. Record aggregate attempt, meaningful result, time band, understood evidence, unsupported reason, comparison and optional account interest without collecting file data. An upload, button click or registration alone is not a meaningful discovery. Use a person who can state a correct practical takeaway as the primary pilot measure. Initial hypotheses: at least 8 of 10 permitted first-time users with an in-scope bill reach a correct finding in 60 seconds without help, and at least 8 can open the evidence and explain what the bill does not establish. Track the denominator for unsupported bills and time spent correcting, and record category-level results separately. Ten users can guide scope, with no claim of a conversion lift.

After a separate rollout approval, compare bill-intent versus broad-product entry messaging using aggregate qualified visits and useful results. Keep measurement manual until needed. If adopted later, measure public entry impressions/clicks outside the isolated island and use an independently optional survey or an explicitly approved privacy-reviewed aggregate signal. No identifiers, cross-tab tracking, bill content, filenames, issuer IDs, amounts or raw error text. Do not loosen Discovery CSP for analytics. Define optional registrations and repeat use without linking them to bill records. Existing Decision Report purchase verification remains a separate settled-payment and delivered-report measure.

## Stages, checks, and launch criteria

| Stage | Deliverable and exit criteria |
| --- | --- |
| 1. Fixture and scope selection | Establish one layout per category, private authority for actual specimens and exact supported document labels. Keep raw originals out of repository, Notion, artifacts and test recordings. Build synthetic/recreated fixtures and hold out authorized de-identified examples. For each supported layout aim for at least 10 varied in-scope documents including held-out periods, and at least 10 negative/ambiguous documents across categories. Agree on rejection boundaries before evaluating. |
| 2. Local-only implementation | Deliver one internal two-category slice. Add one-bill typed summary first, then map each validated text PDF to the same fields. Every displayed financial result must match the source exactly to the cent or declared kWh precision, every critical field and source pointer must match the reviewed ground truth, and no unsupported or ambiguous case may produce an unconfirmed finding. Aim for at least 90% correct initial extraction without corrections on the in-scope held-out set per template, report numerator/denominator and explicitly reject the rest. Cover due vs billed, revised/duplicate periods, ambiguous rows, overlap/length/leap days, estimates, missing/zero/negative values, offsets and failed reconciliation. Preserve current CSV results. |
| 3. Privacy and UX pilot | Test page and worker network and storage with canary values and real browser APIs, offline after assets load, explicit clear/reset, stale reads, route/Back restoration, malformed inputs and timeouts. Verify desktop, tablet, 390 and 320 px plus mobile Safari and Android Chrome file pickers, keyboard, touch, screen reader, forced colors and reduced motion. Capture reviewed Linux visual baselines, run both exact-head workflows and observed usability with approved access. Any exposed file data, wrong confident finding, unsupported claim, parser that needs CSP relaxation, or unresolved accessibility failure blocks release. |
| 4. Authorized release | Make supported formats and privacy wording live together. Scope the claim to the two qualified layouts and manual fallback. Review the external-communication boundary before outreach. Roll back via a separately approved Hosting change that removes the PDF entry/worker and keeps current local CSV/example journeys. Review measured completion, fallback, support and actual transfer costs before broadening. No Stripe, subscription or report changes are dependencies. |
