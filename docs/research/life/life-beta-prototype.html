    Why each screen looks this way

    1 · Question first

    One box, a real example already filled in, and only the decisions we can genuinely answer. Unsupported ones show as "soon" instead of producing a weak answer.

    2 · Confirm, then three questions

    We read the two options back so mistakes surface early. Clarifying questions are capped at three and each changes the result.

    3 · Estimates you can overwrite

    Every pre-filled figure is tagged. A tag tells you whether a number is a published fact, our estimate, or yours.

    4 · Verdict, then the working

    The answer comes first, on the user's own priorities. It must survive each slider moving one step, or the page says there is no clear winner. Money gaps under 5% are flagged as too small to rely on.

    5 · Share without exposure, sign up only to save

    The shared summary leaves out salaries and rent by default. An account is offered only when it adds something: saving and coming back.

    Beta design rule: no server call holds personal inputs. Price and rent tables would ship as a small static file and the calculation runs in the browser, so anonymous use costs almost nothing and stores nothing.
