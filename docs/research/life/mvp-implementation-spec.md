# ifYouMind Life MVP: implementation-ready specification (job-offer comparison)

**Status:** specification only. The founder approved `/life` as the entry point on 2026-10-15.
- Nothing is built, published or deployed. `/life` is not live.
- No production AI. No anonymous backend function.
- The Business homepage, its functions, and the $79 and $39 prices are unchanged.

## 1. Exact MVP scope
**In scope (one workflow):** "Compare two job offers or locations in the US."
- **Two options**, each with a place (a US place mapped to its metro, or the state nonmetro fallback), an annual salary, monthly housing and commute minutes.
- **One shared tax share**, prefilled with a rough federal + FICA estimate.
- **Optional per option:** monthly commute cost, a 1–5 career rating and a 1–5 "near family and friends" rating.
- **Optional shared inputs:** a relocation-covered flag and a moving cost.
- **Priorities:** four 0–5 weights (money left, commute time, career, family).
- **Outputs:**
  - the monthly money table: take-home, housing, left after housing, buying power;
  - the small-gap flag;
  - the verdict on the user's priorities, or "no clear winner";
  - why the verdict holds or flips;
  - evidence with Fact / Estimate / Yours / Calculation tags and sources;
  - three next steps;
  - a copyable summary with no amounts by default.

**Out of scope for the MVP:**
- AI or free-text understanding (the question box only routes to this workflow);
- accounts and saving;
- share links;
- state or local tax calculation;
- occupation wage checks;
- more than two options;
- non-US places;
- languages other than English.

## 2. Mobile-first page structure
```
/life/                         static pre-rendered landing (crawlable; own title, description, canonical, OG)
  hero: "What are you trying to figure out?"  → one primary action: "Compare two job offers"
  how it works (3 lines), what we use (sources with dates), what we never do (store inputs, ads, lead selling)
  link: /life/compare-job-offers
/life/compare-job-offers       Angular lazy route (standalone components), single column, 360–440px design width
  step 1  Options     two place inputs (autocomplete from the static place list) + salary for each
  step 2  Questions   housing size · relocation covered · what matters most          (max 3)
  step 3  Numbers     prefilled housing per place, commute minutes, tax share; every field tagged
  step 4  Result      verdict card → money table → small-gap note → priorities + ratings → evidence → next steps
  step 5  Share       copy summary (amounts off by default) · "Save comes later" note (no account in MVP)
```
- **State:** kept in memory only. A page reload clears it, with a one-line warning before leaving step 4. No `localStorage` in the MVP.
- **Navigation:** back and next within the route. The browser back button moves between steps (history state holds only the step number, never values).

## 4. Data contracts and official source versions
**Static file:** `src/assets/life/v2024-1.json`, generated by `scripts/build-life-data.mjs` and reviewed in a PR. It is versioned by data year and revision, and served with a long cache.

```ts
interface LifeDataset {
  version: 'v2024-1';
  generated: string;                       // ISO date of the build
  sources: SourceRecord[];
  metros: Record<string /* CBSA code */, MetroFacts>;
  stateNonmetro: Record<string /* state FIPS */, MetroFacts>;
  places: PlaceEntry[];                    // principal cities + places ≥ 20,000 people
  tax: TaxConstants;
}
interface SourceRecord { id: 'bea-rpp-2024' | 'acs5-2024' | 'irs-2026' | 'ssa-2026' | 'omb-2023';
  publisher: string; table: string; dataYear: string; released: string; retrieved: string; url: string; notice?: string; }
interface MetroFacts { name: string; rppAll: number; rppGoods: number; rppServicesOther?: number;
  rentMedian?: { br1?: number; br2?: number; br1Moe?: number; br2Moe?: number };   // ACS B25031, 2020–2024
  sourceIds: string[]; }
interface PlaceEntry { label: string /* "Raleigh, NC" */; stateFips: string; cbsa?: string /* absent = nonmetro */; }
interface TaxConstants { year: 2026; standardDeductionSingle: 16100; brackets: Array<[upTo: number, rate: number]>;
  ssRate: 0.062; ssWageBase: 184500; medicareRate: 0.0145; addlMedicareRate: 0.009; addlMedicareThreshold: 200000; }
```

**Source versions pinned for the MVP:**

| Source | Version | What we use |
|---|---|---|
| BEA Regional Price Parities | 2024 (released 2026-02-19) | `rppAll`, `rppGoods`, and services components where published |
| ACS 5-year | 2020–2024 (released 2026-01-29) | B25031 one- and two-bedroom median gross rent, with margins of error |
| IRS | Rev. Proc. 2025-32 (tax year 2026) | Brackets and the standard deduction |
| SSA | 2026 wage base | Social Security wage base |
| OMB | Bulletin 23-01 delineations | Place → county → CBSA |

**Must be confirmed before PR L2 merges** (Appendix A):
- the BEA table names;
- whether a non-housing composite can be built from published components. If it can't, use `rppAll` and say on the page that it includes rents;
- the Census notice wording;
- the 0.9% Additional Medicare tax rate.

**Result contract** (the browser engine's output; mirrors the WP2 evidence model):
```ts
interface DecisionResult { options: [OptionResult, OptionResult];
  money: { gap: number; relGap: number; small: boolean; leader: 'A'|'B'|'none' };
  verdict: { kind: 'leader'|'no_clear_winner'; leader?: 'A'|'B'; flipsOn: Criterion[] };
  evidence: Evidence[];   // kind: 'fact'|'estimate'|'user'|'calculation', with sourceId or 'user'
  nextSteps: string[]; }
```

## 5. Browser-side calculation architecture
- **Pure TypeScript module** `src/app/life/engine/`: `tax.ts`, `money.ts`, `score.ts`, `verdict.ts`, `evidence.ts` and `summary.ts`.
  - No Angular imports and no I/O. Deterministic.
  - Unit-tested with `node --test`, like `test/evidence-summary.test.mjs`.
- **Tax estimate:** a single filer with the standard deduction.
  - Federal tax comes from the brackets; Social Security is capped at the wage base; Medicare plus the additional 0.9% above $200k.
  - It is shown as an **estimate** with the effective share, and the user can edit it.
  - State and local tax show as "not included" unless the user enters them.
- **Money:**
  - take-home = salary × (1 − tax share) ÷ 12;
  - left = take-home − housing − commute cost;
  - buying power = left ÷ (non-housing price level ÷ 100).
- **Scoring:** each criterion is min-max scaled 0–1 within the pair (lower is better for commute time), then weighted by the 0–5 sliders.
- **Verdict:** there is a leader only if the score gap is at least 0.25 and the leader holds for every ±1 change to any single weight. Otherwise the result is `no_clear_winner`, with the weights that flip it. This is the same rule as the WP2 checker's sensitivity test.
- **Small gap:** a relative money gap under 5% is flagged as a reading aid. The page says it is not a significance test.
- **Claim check in CI:** every sentence template in `summary.ts` is graded with the merged `engine/evidence.ts` `checkClaims`:
  - no verdict without criteria;
  - no ranking inside a small gap;
  - no causal or certainty words.

## 6. Privacy and security safeguards
- **Inputs never leave the browser.** No network request carries user values. The only fetch is the static dataset. This is enforced by an e2e test that fails on any request other than same-origin static assets during the workflow.
- **Nothing is stored:** no cookies, no `localStorage`, no URL parameters with values (step numbers only).
- **No analytics events in the MVP.** Consent-gated step events are a separate PR (L6) that needs privacy approval, and they never carry amounts, places or free text.
- **No backend:** no new Cloud Function, no Firestore access, no App Check dependency. Existing headers apply (Referrer-Policy, CSP).
- **Copy-summary redaction:** salaries and housing are off by default, with an explicit toggle to include them.
- **Legal:**
  - The page says estimates are not financial or tax advice.
  - The Terms and Privacy Policy need consumer-use wording (counsel), before public launch, not before the PRs.

## 7. Accessibility and performance requirements
**Accessibility (WCAG 2.2 AA):**
- every input has a visible label;
- errors are named in text and tied to their field with `aria-describedby`;
- targets are at least 44 × 44 px;
- sliders show their numbers and work from the keyboard;
- evidence tags carry a text label, never colour alone;
- contrast is at least 4.5:1 in both themes;
- `prefers-reduced-motion` is respected;
- the verdict region is announced with `aria-live="polite"`;
- axe checks run in e2e with no serious violations.

**Performance:**
- `/life/` is static HTML+CSS under 60 KB, with no Angular bootstrap.
- The route chunk is at most 150 KB gzipped.
- The dataset is at most 120 KB gzipped, and the place list loads with it.
- LCP is under 2.5 s and INP under 200 ms on a mid-range phone (Lighthouse mobile ≥ 90).
- The workflow works after the first load with no further requests.

## 9. Acceptance tests for the first complete workflow (Playwright, desktop and Pixel 7)
1. **Happy path:** Raleigh, NC $80,000 vs Denver, CO $95,000, two-bedroom, defaults. The verdict screen appears within 5 interactions after salaries. The money table shows four rows per option. Every prefilled figure has a tag.
2. **No clear winner:** with weights that tie or flip on ±1, the card reads "No clear winner" and names the flipping priority. No verdict words such as "stronger" or "better" appear.
3. **Small gap:** with a relative money gap under 5%, the note says the gap is small and could reverse, and contains "not a significance test" in the method text.
4. **User numbers win:** editing housing replaces the estimate tag with "Yours", and the result updates.
5. **Fallback place:** a nonmetro place shows "state nonmetro price level used".
6. **Unknown place:** free text not in the list blocks Next with a clear message and suggestions. Nothing is invented.
7. **Privacy:** during the whole workflow, no network request leaves the origin except the static dataset. No cookie or storage writes. The URL never contains values.
8. **Share redaction:** the copied summary has no `$` amounts by default; with the toggle on, it includes the salaries and housing.
9. **Accessibility:** keyboard-only completion is possible; axe reports no serious violations; 200% zoom has no horizontal page scroll.
10. **Performance budget:** the route chunk is at most 150 KB gzipped (build check), and the dataset is at most 120 KB gzipped.
11. **Business intact:** the existing homepage, sample report, decision flow and checkout e2e suites still pass unchanged.
12. **Evidence:** "Where these numbers come from" lists BEA RPP 2024 and ACS 2020–2024 with release dates and notices.
